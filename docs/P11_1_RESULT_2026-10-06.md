**Status: PARTIAL — code and automated checks PASS; both staging Workers built the feature commit and reached 100%; authenticated staging write E2E remains unverified.**

**Date:** 2026-10-06

## Root causes

- Story's photo picker assumed a paginated Memory response containing `photos`, while the API also registered a legacy array response. The duplicate GET route could shadow the stable contract in generated routing/OpenAPI.
- Story's picker only traversed the first 50 Memories and up to 12 photos per Memory. Memory detail stopped at 50 photos.
- Memory detail had no paginated navigation or retry path after a partially failed upload; photo caption/date metadata had no update endpoint.
- Malformed photo tokens could raise a server error rather than fail as invalid input.
- The editor did not clear an already-loaded album when the selected family context changed.

## Fixed

- Kept one canonical paginated Memory list response and added bounded photo summaries; Memory detail now uses a paginated photo API with visible-person tags and author/edit context.
- Added an authorized photo metadata update endpoint for title, description and date.
- Story editor now pages through Memories and each Memory's photos, previews existing images, edits captions, removes image tokens, and ignores stale requests after family changes.
- Memory create/detail now show local image previews and size, upload progress, partial-failure recovery, paginated thumbnails, protected original preview, metadata editing and confirmed photo deletion.
- Invalid photo tokens now return validation errors; public Story rendering has a safe unavailable-image fallback.
- Video remains explicitly unsupported. The existing secure media pipeline has no video object model, validation/transcoding, poster, playback/range handling or lifecycle support; no fake upload/player control was added.

## Security and privacy

- Reused the current family-scoped Memory/Photo authorization, protected media delivery and canonical Story photo token model.
- Added regression coverage for malformed tokens and rejection of cross-family/private photos in public Stories. Existing private media, guardian and family-scope logic was preserved.
- Story photo tokens reference existing Memory photos; image deletion remains separate from Story token removal.
- No schema migration, seed data, production data, visibility policy, DNS or secrets changed.
